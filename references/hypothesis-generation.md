# 假设生成工作流（D0.5 阶段，对标 Google AI co-scientist 的 Generate→Reflect→Rank→Evolve）

> 用途：在文献综述（D0）之后、方法设计（D1）之前，生成可证伪的研究假设候选。
> 实现载体：`workflow` 工具的 JS 编排脚本（模式见本目录 adversarial_review.workflow.md）。

## 四角色循环

```
[Generator] 发散: 基于 D0 的 GAP 陈述 + 基线池，生成 N 个候选假设
      ↓
[Reflector] 批判: 对每个候选找反例/文献矛盾/可行性障碍（绝不温和）
      ↓
[Ranker]   排序: 按 novelty × feasibility × significance 打分排序
      ↓
[Evolver]  进化: top-k 候选依据批判意见迭代改进（Evolve）
      ↓
      └─────── 循环（Evolver 输出回到 Reflector），≥2 轮
```

## 输出物

写入 `HYPOTHESES.md`，每候选记录：

| 字段 | 要求 |
|---|---|
| id | H01, H02, ... |
| 假设 | 一句话可证伪陈述（含具体数值/方向预期） |
| 依据 | 引 D0 文献池可追溯条目（L## 或 arXiv ID） |
| 反例/风险 | Reflector 的批判（必须诚实记录） |
| 验证实验 | 具体到数据集/指标/对照（D1 可直接用） |
| 预期结果 | 若不成立则如何（预注册精神） |
| novelty | 1-5 分，与文献 gap 对齐说明 |
| feasibility | 1-5 分（数据/算力/时间） |
| 状态 | 候选 / 已进化 / 已采纳 / 已否决 |

## 硬规则

1. **无依据候选标记 "exploratory"**：不能引文献支撑的候选必须显式标注，不得混入
   evidence-based 候选池。
2. **反射必须诚实**：Reflector 找不出反例的候选，要么是证据不足（要继续找），
   要么是 trivially true（要降权）——"完美假设"本身就是危险信号（FM-15 式幻觉）。
3. **进化闭环**：每个被采纳候选必须有一条从 H 到实验的路径；只产出候选不落地
   假设 = 空转。
4. **与 claim ledger 联动**：采纳的假设最终成为 C 类声明时，必须有 HYPOTHESES.md
   溯源（"预先假设 H03，实验支持"比事后包装可信）。
5. **不替代文献综述**：D0.5 依赖 D0 的 GAP 输出；跳过 D0 直接生成 = 幻觉温床。

## 审稿时验证（对应本工作流的对抗检查）

- 每个候选的"依据"是否可追溯（grep 文献池 ID 真实存在）
- 已采纳假设是否有验证实验且在 Results 中可定位
- 是否把 exploratory 候选混入 evidence-based 结论（FM-15 复发检测）

## 实战教训（Phase B 实证，2026-08-14）

四角色循环在 demo 论文（校准主题）上的实战产出：

1. **Reflector 的价值在批判不在生成**：6 个原始候选全部被找出反例/障碍
   （feasibility 1-3/5）——包括"数据合成循环确证"（逐种子 ECE 是构造产物，
   任何'假设被数据支持'都是循环论证）、"TS 基线可疑"（0.0308 在真实 CIFAR-10
   高得不可信）、"统计口径缺陷"（rank-biserial 由 p 反解）。**假设生成循环让
   '该做什么实验'变得明确且诚实**——它揭示了模拟数据的根本不可信，直接催生
   真实训练（Phase A）。
2. **预注册纪律**：Evolver 输出的确认性假设必须有功效分析/等价界/门控预注册，
   否则"成功区域为空"（H1 实战教训：ΔECE ≤ -0.005 的界落在 ECE 估计器分辨率
   量级上，确认性检验在开跑前就注定为空）。
3. **参照系偷换检测**：H5 被 Reflector 抓出"把参照系偷换成 accuracy-invariant
   的 temperature scaling，规避了真正的精度权衡问题"——这是假设设计常见陷阱。
4. **与 claim ledger 联动**：采纳假设（H1-H3）的验证结果必须回溯到
   HYPOTHESES.md 条目（"预先假设 H01，实验支持"）。
